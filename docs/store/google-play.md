# Публикация LeDor в Google Play — пошагово

Для заказчика. Тексты, картинки и ответы на анкеты подготовлены; их нужно перенести в Play Console
(https://play.google.com/console). Названия пунктов консоли даны по-русски и по-английски — интерфейс меняется,
ищите похожие. Требования Google проверять в консоли в момент публикации (`08-store-compliance.md`).

## 0. Что где лежит

| Что | Где |
|---|---|
| Файл для загрузки | `app-release.aab` (собирается `./gradlew :app:bundleRelease`, нужен `android/keystore.properties`) |
| Тексты на 6 языках | `<язык>/listing.txt` — после `node tools/store/build.mjs <каталог>` |
| Значок 512×512 | `icon-512.png` |
| Обложка 1024×500 | `<язык>/feature.png` |
| Снимки экрана 1080×1920 | `<язык>/shot-1.png` … `shot-7.png` |

Картинки снимаются командой `sh <каталог>/render.sh` (нужен Chromium; переменная `CHROME` — путь к нему).
Источник текстов — `tools/store/i18n/<язык>.mjs`; править там, потом пересобрать.

## 1. Создать приложение

«Все приложения» → «Создать приложение» (Create app):

- Название: **LeDor** (полное название с ключевыми словами задаётся на странице приложения, шаг 3).
- Язык по умолчанию: **English (United States) – en-US**.
- Приложение или игра: **Приложение**. Платное или бесплатное: **Бесплатное** (потом сменить нельзя).
- Отметить согласие с правилами и экспортными законами США.

### 2.1. Безопасность данных

- Собирает или передаёт ли приложение данные? **Да.**
- Все данные шифруются при передаче? **Да.**
- Можно ли запросить удаление данных? **Да.** Ссылка: `https://kalendar.bothub.chat/en/privacy/#delete`.
- Учётные записи: **в приложении нельзя создать учётную запись.**

| Тип данных | Собирается | Передаётся третьим лицам | Обязательно | Цель |
|---|---|---|---|---|
| Личная информация → **Имя** (имена людей в событиях общих списков) | да | нет | нет (можно пользоваться только личным списком) | Функции приложения |
| Личная информация → **Адрес электронной почты** (контакт в отзыве, если пользователь его указал) | да | нет | нет | Связь с разработчиком |
| Действия в приложении → **Другой контент, созданный пользователями** (даты, названия, заметки в общих списках; текст отзыва) | да | нет | нет | Функции приложения; связь с разработчиком |
| Сведения о приложении и производительности → **Другие данные о производительности** (модель телефона, версия Android и приложения, язык — только если пользователь оставил галочку в отзыве) | да | нет | нет | Связь с разработчиком |

«Обрабатываются временно» — **нет** во всех строках. Всё остальное (местоположение, контакты, идентификаторы, финансы,
здоровье, фото, файлы, история браузера) — **не собирается**.

### 2.2. Точные будильники (USE_EXACT_ALARM)

Основная функция: **«Календарь»** (Calendar). Обоснование, если нужно ввести текстом:

> LeDor is a calendar app. Its core function is reminding the user of events they created themselves (birthdays,
> yahrzeits, family dates) at the time they chose: the evening before, a set time before local sunset, and on the day.
> Reminders must fire on time because the Hebrew date begins at sunset.

Если Google откажет — `08-store-compliance.md` §3: заменить на `SCHEDULE_EXACT_ALARM`, код менять не нужно.

## 3. Страница приложения (Main store listing)

«Развитие» → «Страница приложения» (Grow → Store presence → Main store listing):

1. Из `en/listing.txt`: название, краткое и полное описание.
2. Значок — `icon-512.png`; обложка — `en/feature.png`; снимки телефона — `en/shot-1…7.png`. Снимки планшета не нужны.
3. «Перевод» → «Добавить свой перевод» (Manage translations → Add your own translation): русский `ru-RU`, иврит `iw-IL`,
   французский `fr-FR`, испанский `es-ES`; для каждого — тексты из `<язык>/listing.txt`, обложка и снимки из той же папки.
   **Идиша в списке языков Google Play может не быть** — тогда пропустить: идишеязычные пользователи увидят английскую страницу,
   а приложение у них всё равно на идише.

«Настройки магазина» (Store settings):

- Категория: **Образ жизни** (Lifestyle). Теги — до пяти подходящих из списка консоли (календарь, напоминания, религия…).
- Адрес электронной почты: **публичная почта поддержки** (обязательно, видна всем) — тот же адрес, что в политике конфиденциальности (D-40).
- Сайт: `https://kalendar.bothub.chat`. Телефон — не указывать.

## 4. Внутреннее тестирование — поставить себе (без проверки Google)

«Тестирование» → «Внутреннее тестирование» (Internal testing):

1. «Тестировщики» → создать список, добавить свой Gmail.
2. «Создать выпуск» → на вопрос о ключе подписи приложения — **«Использовать ключ, созданный Google»**
   (Play App Signing; рекомендуемый вариант). Загрузить `app-release.aab`. Примечание к выпуску — «Что нового» из `listing.txt`.
3. «Сохранить» → «Проверить выпуск» → «Начать развёртывание».
4. Во вкладке «Тестировщики» скопировать ссылку для участия, открыть её на телефоне, принять приглашение, установить из Google Play.

**Перед установкой из Google Play удалите LeDor, поставленный с сайта:** подпись другая, поверх не встанет.
Личный список при удалении пропадёт; общие списки вернутся после подключения по названию и ПИН-коду.

## 5. Закрытое тестирование — обязательно для нового личного аккаунта

> Заказчик ждёт D-U-N-S для компании Axiomatic Intelligence, Inc. (D-40). Аккаунту организации закрытое тестирование не нужно:
> тогда `org.ledor` переносится в него, и этот шаг пропускается. Запасной вариант — закрытое тестирование через Google Group на личном аккаунте.

Google требует перед выходом в рабочую версию: **не менее 12 тестировщиков, непрерывно подключённых 14 дней**
(требование 2025 года — проверить на панели консоли, там же счётчик).

1. «Тестирование» → «Закрытое тестирование» → трек «Closed testing (Alpha)» → «Тестировщики»: список Gmail-адресов
   (лучше 15–20, с запасом) или Google-группа.
2. Страны: все.
3. «Создать выпуск» → тот же `.aab` (или «Добавить из библиотеки») → отправить на проверку. Первая проверка — от нескольких часов до нескольких дней.
4. После одобрения разослать тестировщикам ссылку для участия. Каждый: открыть ссылку → «Стать тестировщиком» →
   установить из Google Play → не удалять 14 дней. Желательно, чтобы приложением правда пользовались: Google спрашивает об этом.

## 6. Рабочая версия

Через 14 дней на панели — «Подать заявку на доступ к рабочей версии» (Apply for production). Ответить на вопросы
о тестировании (сколько человек, какие отзывы, что исправили). Потом «Рабочая версия» → «Создать выпуск» →
`.aab` из библиотеки → страны: все → отправить на проверку.

## 7. После выхода (исполнитель)

- На сайте — официальный значок Google Play и ссылка вместо серой плашки; ответ «Скоро» в вопросах — убрать для Android.
- В приглашении к списку (`APP_LINK`) — ссылка на страницу в Google Play.
- APK на сайте подписан тем же ключом загрузки, а приложение из Google Play — ключом Google, поэтому одно поверх другого
  не ставится. После выхода APK на сайте оставить как запасной вариант и предупредить об этом рядом с кнопкой.

## Ключ загрузки

- Лежит в `android/keystore/ledor-upload.jks`, пароль — в `android/keystore.properties`. Оба файла в Git не попадают.
- **Копия ключа и пароля должна храниться у заказчика вне сервера** (менеджер паролей, облако).
- Если ключ загрузки потерян, его можно заменить через поддержку Google Play: приложение подписывает Google своим ключом,
  поэтому обновления не теряются. Но без ключа загрузки нельзя выпустить обновление, пока Google не подтвердит замену.
