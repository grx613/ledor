# Решения, допущения и открытые вопросы

Живой документ (обновлён 2026-11-24). Исполнитель дописывает сюда каждое новое решение (дата · что · почему).
§1 — действующие решения, §3 — что ещё не решено, §5 — журнал: как и почему менялось по ходу работы.

## 1. Принятые проектные решения

| № | Решение | Почему |
|---|---|---|
| D-01 | Монорепозиторий: `android/` (модули `:domain` + `:app`), `ios/`, `supabase/migrations/`, `website/`, `tools/` | общий контракт, общие эталонные векторы, один источник ТЗ |
| D-02 | `minSdk 26`, `targetSdk 36`, `compileSdk 37.1` | `java.time` и каналы уведомлений без условий; покрытие устройств > 97 %; `compileSdk 37.1` — минимум, которого требует Compose UI 1.13 |
| D-03 | KosherJava **3.1.0**, изолирована в `HebrewCalendarMath` и `CitySunsetProvider` | актуальная версия на `java.time`; изоляция защищает от смены API |
| D-04 | Без SDK: свой тонкий клиент сервера (Android — OkHttp, iOS — `URLSession`) | нужны 8 POST-запросов; SDK увеличивает размер и время старта |
| D-05 | Без DI-фреймворков, ручной `AppContainer` | быстрее старт, нет процессоров аннотаций и конфликтов версий |
| D-06 | Доступ к серверу только через RPC (`security definer`), таблицы в закрытой схеме; после ввода ПИНа устройство получает токен | ПИН нельзя проверить политиками RLS; токен позволяет не хранить ПИН на сервере в сессиях и не блокировать уже подключённых |
| D-07 | Защита от перебора: блокировка на уровне списка, растущая от 15 минут до 24 часов; плюс лимит по IP | короткий ПИН иначе перебирается за минуты. Компромисс: злоумышленник может мешать новым подключениям к списку; существующие участники не страдают |
| D-08 | Обычный ПИН хранится открытым текстом, Мастер-ПИН — bcrypt | редактор должен видеть обычный ПИН, чтобы делиться списком; мастер не восстанавливается никогда |
| D-09 | Синхронизация: локальная очередь (`sync_state`), на сервере побеждает последняя запись; счётчик ревизий списка вместо времени | работает офлайн, не зависит от часов устройств |
| D-10 | Напоминания — «цепочка из одного будильника» (`setExactAndAllowWhileIdle`) + `USE_EXACT_ALARM` | минимум пробуждений; план всегда вычисляется из базы, рассинхронизация невозможна |
| D-11 | Григорианское 29 февраля в невисокосный год отмечается 28 февраля | самый распространённый обычай; дата остаётся в «своём» месяце |
| D-12 | Йорцайт без года смерти для 30 Хешвана / 30 Кислева: правило «первой годовщины» не применяется (30-е, а в короткий год — 1-е число следующего месяца) | без года первую годовщину определить нельзя |
| D-13 | Еврейский месяц хранится строковым кодом из 14 значений (`ADAR`, `ADAR_I`, `ADAR_II` различаются) | однозначно без года; одинаково на Android, iOS, сервере и сайте |
| D-14 | Правила годовщин совпадают с Hebcal; йорцайт умершего в Адар простого года в високосный год — Адар I (ашкеназский обычай), параметр `YahrzeitAdarPolicy` позволяет Адар II | проверяемость эталонными векторами; сефардский обычай включается настройкой (P2) |
| D-15 | Пол человека не хранится; для дня рождения показываются обе подсказки (бар- и бат-мицва) | меньше персональных данных и полей ввода |
| D-16 | День рождения и йорцайт «наступают» начиная со следующего года после исходной даты; свадьба и прочие — с исходной | уведомление «исполняется 0 лет» бессмысленно, а предстоящая свадьба — событие |
| D-17 | Расписание напоминаний одинаково для событий по обоим календарям; «накануне» считается от захода солнца предыдущего дня | простая и предсказуемая модель; различается только текст |
| D-18 | Сайт статический, без библиотек; страницы на шести языках собирает свой генератор без зависимостей (`tools/site/build.mjs`); календарь на JS написан заново. Hebcal — только dev-инструмент для генерации векторов | сайт грузится мгновенно и выкладывается копированием файлов; шесть языков руками не поддержать |
| D-19 | Шесть языков: en (по умолчанию), he, ru, yi, fr, es; иврит и идиш — справа налево, еврейские даты буквами | где живут пользователи (BACKLOG B-6); английский — запасной язык |
| D-20 | Все автотесты — на JVM (JUnit, Robolectric, Roborazzi) | на машине разработки нет аппаратной виртуализации, эмулятор недоступен |
| D-21 | Локальный список один («Личный»); «Создать список» всегда создаёт облачный | простая модель; смысл отдельных списков — в совместном доступе |
| D-22 | Список, удалённый владельцем, автоматически исчезает с остальных телефонов при синхронизации | удаление из облака должно быть настоящим (требование магазинов и здравый смысл приватности) |
| D-23 | Брендовая заставка LeDor 1500 мс, идёт параллельно загрузке данных | «пара секунд» по ТЗ при минимальной задержке запуска |
| D-24 | Собственная палитра (тхелет + золото), без динамических цветов Material You; шрифт Rubik | узнаваемый облик; один шрифт на кириллицу, латиницу и иврит |
| D-25 | Название — **LeDor**, слоган «LeDor VaDor / לדור ודור», надпись «Kalendář»; идентификатор `org.ledor`; свой знак (лист календаря с Маген Давидом), бренда BotHub в приложении нет | решения заказчика (B-9, B-10, B-13); идентификатор после публикации не меняется |
| D-26 | Сервер свой: PostgreSQL + PostgREST за Caddy на `kalendar.bothub.chat`, тот же контракт, что был на Supabase | не зависеть от тарифов Supabase (B-11); клиент и миграции не пришлось менять |
| D-27 | «По обоим календарям» хранится значением `observe_by = 'BOTH'`, основной календарь — календарь ввода | без нового столбца и миграции Room; старые версии читают как «по еврейскому» |
| D-28 | Отзывы: RPC `submit_feedback` → таблица на сервере → пересылка автору в Telegram; почты поддержки нет | работает без настроенной почты у пользователя; токен бота — только на сервере |
| D-29 | Контакты: автор «Гершон», канал `t.me/bothub_founder`; личный Telegram не публикуется | решение заказчика (B-4, B-16) |
| D-30 | Код открыт на GitHub (`github.com/grx613/ledor`) под GPL-3.0 | производные версии должны оставаться открытыми; KosherJava (LGPL) совместима |
| D-31 | Подсказка «до или после захода»: сумерки — от захода до 8,5° под горизонтом (или 72 минуты); в сумерках приложение ничего не решает за пользователя | дата в сумерках — галахическое сомнение |
| D-32 | Сайт презентует приложение вокруг двух обещаний (напоминает; списком легко поделиться); шапка без меню; конвертер — отдельная страница | замечания заказчика (B-23) |
| D-33 | Google Play: Play App Signing с ключом, созданным Google; свой ключ загрузки подписывает и `.aab`, и APK для сайта | потерю ключа загрузки можно восстановить через поддержку Google; APK с сайта и из магазина друг поверх друга не ставятся — принято |
| D-34 | Прямой запрос «не экономить батарею» и служба переднего плана WorkManager убраны из сборки | правила Google Play; LeDor их не использует (05 §1) |
| D-35 | Список «Еврейские праздники» — встроенный и вычисляемый: в базе и на сервере его нет, события подмешиваются как разовые; настройки — в DataStore | не нужна миграция и изменение контракта сервера; названия на языке приложения; правила с переносами нельзя выразить «повтором по дате» |
| D-36 | Напоминания о праздниках и Шабате — только накануне вечером; Шабат выключен по умолчанию и требует города | в праздник и Шабат соблюдающие телефоном не пользуются; еженедельное напоминание — по желанию, чтобы не перегружать |
| D-37 | Обычай (Израиль / диаспора) определяется по городу, отдельной настройки нет; зажигание свечей — 18 минут до захода (Иерусалим 40, Хайфа 30) | меньше настроек; значения — как у Hebcal |
| D-38 | Векторы праздников и свечей берутся из открытого API Hebcal скриптом без зависимостей (`tools/golden/holidays.mjs`) | пакет `@hebcal/core` в генератор добавить не удалось (установка новых пакетов в этой среде запрещена); источник тот же — Hebcal |
| D-39 | Вехи первого года считаются от дня смерти, без даты похорон и без сокращения шлошим праздниками; шива не считается; в карточке — пояснение и совет уточнить у раввина | в событии одна дата; правила сокращения сложны и различаются по общинам — ошибка здесь хуже, чем честная оговорка |
| D-40 | Публичная почта поддержки — пока личная почта заказчика: она в политике конфиденциальности на сайте, в Google Play и App Store. Название и тексты в App Store — те же, что в Google Play (`tools/store/i18n`; разметка App Store — `tools/store/appstore/`). APK на сайте — всегда последняя версия, и до выхода в магазин тоже. ~~Имя разработчика в обоих магазинах — личное имя заказчика~~ — **заменено 2026-11-25:** продавец в обоих магазинах — компания заказчика Axiomatic Intelligence, Inc. (ждём D-U-N-S; затем аккаунт организации в Google Play и перенос `org.ledor` в него — тогда закрытое тестирование 12 × 14 не нужно; запасной вариант — закрытое тестирование через Google Group на личном аккаунте) | решение заказчика 2026-11-25; отдельный адрес поддержки можно завести позже, ничего не переделывая |
| D-41 | iOS: проект Xcode пишется руками без генераторов (группа `LeDor/` синхронизируется с папкой), Swift 6, iOS 17+, только iPhone, идентификатор `org.ledor`; логика — локальный пакет `ios/Domain`, тесты — Swift Testing | нет лишних инструментов на Mac; новые файлы в `LeDor/` подхватываются сами; без iPad не нужны снимки для iPad в App Store |
| D-42 | iOS: хранение — один JSON-файл (`LocalStore`), не SwiftData и не SQLite; настройки — JSON в UserDefaults | данных мало (сотни событий); запись атомарная; логика хранения и синхронизации тестируется `swift test` без симулятора |
| D-43 | iOS: заход солнца и выход звёзд — свой порт NOAA с поправками как в KosherJava; еврейский календарь — порт `hebrew-calendar.js`, без Foundation `.hebrew` | KosherJava на iOS нет, библиотеки под GPL/LGPL брать нельзя; одни и те же векторы и контрольные значения проходят на обеих платформах |

| D-45 | Кнопка «Открыть настройку» для экономии батареи ведёт на страницу приложения в настройках («Батарея» → «Не ограничено»), а не в общий список оптимизации (Android 0.6.1) | на Samsung общий список по умолчанию показывает только приложения, которые уже не оптимизируются, и LeDor там не найти (сообщил заказчик 2026-11-26); прямой запрос без разрешения `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` невозможен, а разрешение убрано по правилам Google Play. На iOS не касается |
| D-46 | У наступления по григорианскому календарю показывается только григорианская дата; еврейская дата того же дня не выводится (списки, карточка, редактор, уведомление «в день события»). У наступления по еврейскому — обе даты. Событие «по обоим календарям» в списках — две строки, в карточке — два блока (Android 0.6.3) | заказчик: «день рождения 30 апреля и 28 Нисана, а показывает 23 Нисана» — это еврейская дата самого 30 апреля, её читают как еврейский день рождения. Вторая строка для «по обоим» была в ТЗ (ALL-3), но в коде показывалась одна ближайшая дата; напоминания приходили на обе и раньше. На iOS — так же |
| D-47 | Сессии на сервере и на Mac общаются записками в Git: `docs/sync/to-mac.md` пишет только сервер, `docs/sync/to-server.md` — только Mac. Отправка записок — как у остального кода, по просьбе заказчика | решение заказчика 2026-11-26: не пересылать файлы руками. У каждого файла один автор — нет конфликтов слияния (в общем журнале `PLAN.md` они случались дважды) |
| D-48 | Сессия на сервере коммитит и отправляет в Git готовую работу и записки `docs/sync/` без отдельной команды заказчика; условия — в правиле 12 `CLAUDE.md`. На сессию на Mac разрешение не распространяется | заказчик, 2026-11-26: «официально даю разрешение пушить в Git без моего спроса» — сказано сессии на сервере |

## 2. Допущения по неоднозначным местам ТЗ (подтвердить у заказчика)

| № | Допущение | Альтернатива |

## 5. Журнал: как менялись решения (заполняет исполнитель)

Исторические записи; в них встречаются старые названия (Kalendar, Supabase, `chat.bothub…`, GitLab).

| Дата | Веха | Что изменено относительно документов | Почему |
|---|---|---|---|
| 2026-11-24 | M0–M13 (первая тестовая сборка) | Строки интерфейса пока только русские и лежат в `values/` (а не en в `values/` + ru в `values-ru/`); `locale_tag` = ru. Английский перевод — при доводке M13 | заказчик попросил APK для проверки как можно быстрее |

| 2026-11-24 | M6 | Логотип BotHub FiRe и значки типов событий нарисованы кодом (Canvas), а не VectorDrawable | точное воспроизведение SVG с радиальным свечением |

- **2026-11-24, B-6.** `values/` — теперь английский, русский переехал в `values-ru/` (как требует CLAUDE.md). Иврит — `values-iw`, идиш — `values-ji` (старые коды: Android сопоставляет he→iw и yi→ji; с `values-yi` Robolectric не подхватывал строки). Выбор языка без AppCompat: Android 13+ — `LocaleManager`, 8–12 — `SharedPreferences` + `attachBaseContext` (Activity, Application, уведомления). Новых зависимостей нет.
- **2026-11-24, B-1.** Вместо нового столбца — значение `observe_by = 'BOTH'`; основной календарь при этом — календарь ввода. Старые версии приложения прочтут BOTH как «по еврейскому».
- **2026-11-24, B-11.** Вместо Supabase — PostgreSQL + PostgREST на своём сервере с тем же адресом `/rest/v1/rpc/*`, поэтому `SupabaseRpc` и миграции не меняются. `Authorization` срезается в Caddy (PostgREST без JWT), ключ `apikey` проверяет Caddy. Заголовок `cf-connecting-ip` при обращении к серверу в обход Cloudflare можно подделать — это ослабляет только лимиты по IP, не защиту ПИН-кодов (она по списку).
- **2026-11-24, B-2.** Отзыв отправляется сразу; без сети текст остаётся на экране (очередь через WorkManager не делалась). «Пожаловаться на список» открывает тот же экран отзыва вместо письма — почты поддержки нет.
- **2026-11-24, сайт.** Cloudflare кеширует `.apk` на 4 часа в каждом своём узле, поэтому по старой ссылке `/ledor.apk` часть людей получала 0.2.0. Теперь APK выкладывается с версией в имени (`/ledor-0.3.0.apk`), ссылка на главной меняется при каждом выпуске.
- **2026-11-24, сайт (B-19).** Страницы не пишутся руками: `tools/site/build.mjs` + словари `tools/site/i18n/<lang>.mjs`, результат в `website/` коммитится. Имя APK для ссылок — `tools/site/apk-name.txt`. Корень `/` и старые `/privacy/`, `/converter/` — страницы с выбором языка по `navigator.languages` (uk/be/kk → ru, иначе en) и запоминанием в `localStorage`; поисковикам — hreflang и x-default. Контакты (B-16): только канал и форма отзыва; личный Telegram с сайта убран.
- **2026-11-24, тесты.** Снимки на разных языках падали при запуске в одном JVM (DataStore — синглтон процесса). `unitTests.all { forkEvery = 1 }` — медленнее, зато независимо.
- **2026-11-24, сайт (B-23).** Шрифт Rubik отдаётся как `ttf` (тот же файл, что в приложении, ~360 КБ, по сети сжимается brotli) с `font-display: swap`: `07-website.md` допускает локальный Rubik в `woff2`, но конвертера на машине нет (установка пакета была отклонена). При случае заменить на `woff2`. Значки магазинов — собственные нейтральные плашки «Скоро в …», а не официальные значки Google Play / App Store (их правила запрещают перекрашивать); при публикации заменить на официальные. Картинки снимков подключаются с `?v=<ASSET_V>` — иначе Cloudflare до 4 часов отдаёт старые. Имена списков на снимках — примеры («Община Хабад Нью-Йорк» — по просьбе заказчика).
- **2026-11-24, B-24.** Сумерки в подсказке — от захода (уровень моря) до выхода звёзд при 8,5° под горизонтом; если солнце так низко не опускается, берётся заход + 72 минуты. Расчёт остаётся внутри `CitySunsetProvider` (правило про KosherJava). Часовой пояс — исторический из tzdata по `zoneId` города; для дат до ~1970 он может быть неточным в некоторых регионах.
