# План реализации

Исполнитель — модель Claude Opus в Claude Code. План разбит на вехи так, чтобы каждая:
помещалась в одну сессию, имела проверяемый результат и не требовала догадок.

## Как работать с планом

1. **Одна веха — одна сессия.** Команда для запуска: «Выполни веху M<N> из docs/PLAN.md».
2. В начале сессии прочитать `CLAUDE.md`, блок своей вехи и **только** документы из строки «Читать».
3. Порядок внутри вехи: тесты → код → проверка → отметить чекбоксы → запись в «Журнал» внизу файла.
4. Веха готова, когда выполнено всё из «Готово, когда» **и** общие критерии:
   - проходит полная проверка: `source tools/env.sh && cd android && ./gradlew :domain:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`
     (до появления модуля `:app` — только доступные задачи);
   - в коде вехи нет заглушек, `TODO` и строк интерфейса вне ресурсов;
   - отклонения от документов и новые решения записаны в `docs/DECISIONS.md`;
   - для вех с интерфейсом: снимки экранов сделаны и просмотрены.
5. Если документ противоречит реальности (API библиотеки изменился, сборка требует другого) — не «чинить»
   обходными путями молча: выбрать решение, ближайшее к замыслу, и записать в `DECISIONS.md`.
6. Если не хватает ответа заказчика (раздел «Открытые вопросы» в `DECISIONS.md`) — использовать значение по умолчанию
   оттуда и двигаться дальше.

Размер вех: **S** — до часа работы модели, **M** — 1–2 часа, **L** — 2–4 часа.
Рекомендуемые контрольные точки с ревью (`/code-review`) — после M3, M4, M12 и перед M15.

## M0. Окружение и каркас проекта

**Читать:** `02-architecture.md` §1–3, §10.

На машине нет JDK и Android SDK, прав `sudo` может не быть — всё ставится в домашний каталог.

- [ ] `git init` (ветка `main`), если репозитория ещё нет. `.gitignore` уже есть — дополнить при необходимости.
- [ ] JDK 21 (Temurin) → `~/.local/opt/` (архив: `https://api.adoptium.net/v3/binary/latest/21/ga/linux/x64/jdk/hotspot/normal/eclipse`; архитектуру проверить `uname -m`).
- [ ] Android SDK → `~/Android/Sdk`: «Command line tools only» (актуальная ссылка — на `developer.android.com/studio`),
      распаковать в `cmdline-tools/latest`; `yes | sdkmanager --licenses`;
      `sdkmanager "platform-tools" "platforms;android-37.1" "build-tools;36.0.0"`. Нет `unzip` — `python3 -m zipfile -e`.
- [ ] `tools/env.sh` — экспортирует `JAVA_HOME`, `ANDROID_HOME`, дополняет `PATH` (пути от `$HOME`, без имён пользователей).
- [ ] Gradle Wrapper 9.9.2 в `android/` (скачать дистрибутив во временный каталог → `gradle wrapper --gradle-version 9.9.2`).
- [ ] `android/gradle/libs.versions.toml` с версиями из `02-architecture.md` §2.
- [ ] `settings.gradle.kts`, корневой `build.gradle.kts`, модули `:domain` (Kotlin/JVM, toolchain 21) и `:app`
      (Compose, `minSdk 26`, `targetSdk 36`, `compileSdk 37.1` — синтаксис в `02-architecture.md` §2,
      `applicationId chat.bothub.fire.kalendar`).
- [ ] `android/local.properties.example` (`sdk.dir`, `supabase.url`, `supabase.key`); реальный `local.properties` не коммитится.
      Поля `BuildConfig.SUPABASE_URL` / `SUPABASE_KEY` (пустые строки по умолчанию).
- [ ] В `:app` — `MainActivity` с пустым Compose-экраном; в `:domain` — один тривиальный тест.
- [ ] `android/README.md`: как собрать, как запустить тесты, как поставить на телефон (`adb install`).

**Готово, когда:** полная проверка проходит с нуля на чистом клоне после `source tools/env.sh`; получен `app-debug.apk`.
Фактические версии (если пришлось менять) записаны в `DECISIONS.md`.

**Внимание:** AGP 9 — встроенный Kotlin, см. `02-architecture.md` §2. При ошибках конфигурации сначала читать
официальную документацию AGP, а не подбирать варианты.
