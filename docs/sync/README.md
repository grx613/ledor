# Связь между сессиями

Над LeDor работают две сессии Claude Code. Друг друга они не видят и общаются только через файлы в этой папке (решение заказчика, 2026-11-26, D-47).

| Сессия | Где работает | За что отвечает | Пишет в | Читает |
|---|---|---|---|---|
| **сервер** | Linux, сервер `kalendar.bothub.chat` | Android (`android/`), сайт, бэкенд, `tools/store/i18n/`, документы `01`–`08`, `store/` | `to-mac.md` | `to-server.md` |
| **Mac** | macOS заказчика | iOS (`ios/`, `docs/09-ios-notes.md`), `tools/store/appstore/`, консоли Google Play и App Store через браузер | `to-server.md` | `to-mac.md` |

## Правила

1. **Когда читать.** В начале сессии, перед правкой общих файлов и по слову заказчика «проверь почту»: `git pull`, затем прочитай свой входящий файл.
2. **Куда писать.** Только в свой исходящий файл. Чужой файл не править никогда — поэтому конфликтов здесь не бывает.
3. **Формат.** Одна тема — одна запись. Новые записи — сверху, сразу под шапкой файла:
   ```
   ## S-2 · 2026-11-27 · Короткая тема
   Статус: открыто
   Текст записки.
   ```
   Номера: `S-…` — от сервера, `M-…` — от Mac, по порядку.
4. **Ответ.** Отвечай новой записью в своём файле: «Ответ на S-2: сделано / не сделано / вопрос» и подробности. Получив ответ, автор меняет у своей записи статус на «закрыто». Закрытые записи старше двух недель удаляй: они остаются в истории Git.
5. **Что писать.** Только то, что нужно второй сессии: задачи, изменения поведения, которые надо повторить на другой платформе, правки общих файлов (`docs/*`, `spec/*`, `supabase/*`), вопросы. Записка должна быть понятна без заказчика: что сделать, где смотреть, что не трогать, когда остановиться и спросить его. Сделанная работа по-прежнему записывается в «Журнал» `docs/PLAN.md`.
6. **Отправка** — по правилу 12 из `CLAUDE.md`. Сессия на сервере отправляет записки сама (заказчик разрешил 2026-11-26, D-48). Сессия на Mac — по слову заказчика («пуш», «отправь почту»), пока он не разрешил ей иначе: написал записку — скажи ему, что она ждёт отправки.
   ```bash
   git pull && git add docs/sync && git commit -m "sync: S-2 короткая тема" && git push
   ```
   Не прошёл `git push` — `git pull --rebase` и ещё раз.
7. **Репозиторий открытый.** Не писать сюда ключи, пароли, почтовые адреса и личные данные.
8. **Общие файлы** (`PLAN.md`, `DECISIONS.md`, `BACKLOG.md`, `CLAUDE.md`): перед правкой `git pull`, только дописывать, после правки проверить `git diff --stat`. Конфликт в журнале `PLAN.md` — оставить строки обеих сторон.
