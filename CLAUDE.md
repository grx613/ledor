# LeDor — правила для исполнителя

Нативное приложение-напоминалка о днях рождения, йорцайтах и семейных событиях по еврейскому и григорианскому
календарям, с общими списками для семьи и общины; свой сервер и сайт. Название — **LeDor** (слоган «LeDor VaDor»,
надпись «Kalendář»), автор — Гершон. Общение с заказчиком — на русском.

## Состояние (2026-11-25)

| Часть | Состояние |
|---|---|
| Android (`android/`) | версия 0.6.3, пакет `org.ledor`; раздаётся APK с сайта; идёт публикация в Google Play (`docs/PLAN.md`, M15; пошагово — `docs/store/google-play.md`) |

Образец поведения — Android-приложение. Документы описывают текущее состояние; если документ и код расходятся — прав код,
а документ надо исправить.

## С чего начинать сессию

1. `git pull`. Над проектом работают две сессии — на сервере (Android, сайт, бэкенд) и на Mac (iOS, консоли магазинов);
   они общаются записками в `docs/sync/`. Прочитай `docs/sync/README.md` и свой входящий файл: сессия на сервере —
   `to-server.md`, сессия на Mac — `to-mac.md`. Так же — когда заказчик говорит «проверь почту».
2. Прочитай этот файл и `docs/PLAN.md` («Что дальше»). Для iOS — `docs/09-ios-notes.md`.
3. Прочитай только документы, относящиеся к задаче. Не читай всё подряд.
4. Работай в порядке: тесты → код → проверка → обновить документы → запись в «Журнал» в `PLAN.md`.
5. Сделал то, что касается второй сессии (поведение, которое надо повторить на другой платформе, общие файлы, задача
   для неё), — оставь записку в своём исходящем файле в `docs/sync/`. Отправка — по правилу 12.

## Команды

```bash
source tools/env.sh                                   # JAVA_HOME, ANDROID_HOME
cd android && ./gradlew :domain:test                  # быстрые тесты логики
cd android && ./gradlew :domain:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug   # полная проверка
cd android && ./gradlew :app:recordRoborazziDebug     # снимки экранов → app/build/screens/<язык>/
cd android && ./gradlew :app:assembleRelease :app:bundleRelease   # APK и AAB (подпись — android/keystore.properties)
node tools/store/build.mjs dist/store && sh dist/store/render.sh   # тексты и картинки для Google Play
node --test website/tests/*.test.mjs                  # тесты календаря сайта
node tools/site/build.mjs                             # собрать страницы сайта из tools/site/i18n/*.mjs
tools/deploy/publish.sh                               # выложить website/ на kalendar.bothub.chat (на сервере)
cd ios/Domain && swift test                          # iOS: тесты логики (на Mac)
python3 ios/tools/strings.py                          # iOS: тексты из strings.xml Android → Localizable.xcstrings
cd ios && xcodebuild -project LeDor.xcodeproj -scheme LeDor -destination 'platform=iOS Simulator,name=iPhone 17' -derivedDataPath build/DerivedData build   # iOS: сборка
SUPABASE_URL=https://kalendar.bothub.chat SUPABASE_KEY=<публичный ключ> node --test tools/rpc-smoke/smoke.mjs   # проверка сервера
cd tools/golden && npm ci && node generate.mjs        # пересоздать эталонные векторы (обычно не нужно)
node tools/golden/holidays.mjs                        # векторы праздников и свечей из API Hebcal (обычно не нужно)
```

## Нерушимые правила

1. **Только натив.** Android — Kotlin + Jetpack Compose, iOS — Swift + SwiftUI. Никаких Flutter, React Native,
   Compose Multiplatform, WebView-экранов.
2. **Батарея.** Запрещены: foreground-сервисы, wake lock'и, геолокация, Firebase/FCM/Play Services, push-серверы, аналитика,
   WebSocket/Realtime, `setRepeating`, фоновые задачи чаще раза в сутки. Подробно — `05-reminders-battery.md` §1.
3. **Календарь — только через тесты.** Любой код, считающий еврейские даты, сначала получает тест на
   `spec/golden/*.json`. На Android KosherJava вызывается только из `HebrewCalendarMath` и `CitySunsetProvider`.
   Тест на эталонных векторах не проходит → ошибка в коде, не в векторах. Векторы не править.
4. **KosherJava — версия 3.1.0, API на `java.time`.** То, что ты помнишь про `JewishDate(Date)` / `Calendar`, устарело.
   Сигнатуры — в `03-calendar-domain.md` §2.
5. **AGP 9: Kotlin встроен** в плагин Android. При ошибках сборки сверяйся с официальной документацией, а не с памятью.
6. **Сервер.** Клиенты вызывают только RPC-функции. Функции возвращают JSON-конверт `{ok, error}` и **не используют
   `RAISE`** для бизнес-ошибок. Изменения схемы — только новым файлом миграции. Контракт общий для Android и iOS:
   менять его можно только совместимо со старыми версиями приложений.
7. **Тексты — только в ресурсах и на шести языках** (en — по умолчанию, ru, he, yi, fr, es): Android —
   `res/values*/strings.xml`, сайт — `tools/site/i18n/*.mjs`. Новая строка добавляется сразу во все языки.
   Страницы `website/<lang>/` руками не править — они генерируются.
8. **Зависимости.** Новая библиотека — только с записью и обоснованием в `DECISIONS.md`. Версии Android — в `libs.versions.toml`.
   В iOS-версию не брать библиотеки под GPL/LGPL.
9. **Секреты и личные данные.** `local.properties`, ключи подписи, токены, публичный ключ сервера — не коммитить.
   В код и документы не вставлять абсолютные пути домашнего каталога и почтовые адреса людей. Личные контакты автора,
   кроме канала `t.me/bothub_founder`, не публиковать.
10. **Правда в текстах.** На сайте и в приложении писать только то, что реализовано. В отчёте заказчику честно указывать,
    что не сделано или не проверено.
11. **Документы — часть работы.** Изменил поведение — в той же работе обнови соответствующий документ, `DECISIONS.md`
    и «Журнал» в `PLAN.md`. Идеи заказчика записывай в `BACKLOG.md`; делать их — после его команды.
12. **Git.** Ветка — `main`. **Сессия на сервере** коммитит и отправляет (`git push`) готовую работу и записки
    `docs/sync/` сама, не спрашивая: заказчик разрешил это 2026-11-26 (D-48). Условия: перед этим `git pull`; для кода —
    полная проверка проходит; в коммите нет секретов; без `--force` и переписывания истории. В отчёте заказчику — что
    отправлено. **Сессия на Mac** — по просьбе заказчика, пока он не разрешил ей иначе.

## Когда что-то не сходится

- Документ противоречит реальному API или сборке → выбери решение, ближайшее к замыслу, запиши в `DECISIONS.md` §5, продолжай.
- Не хватает ответа заказчика → возьми значение «По умолчанию» из `DECISIONS.md` §3, продолжай.
- Два документа противоречат друг другу → приоритет: `03` (календарь) > `04` (сервер) > `05` > `01` > `02` > `06`; исправь оба.

## Самопроверка перед завершением работы

- [ ] Полная проверка проходит (тесты, lint, сборка).
- [ ] Для экранов: снимки открыты и просмотрены (светлая и тёмная тема; ru, en, he).
- [ ] Нет `TODO`, заглушек и закомментированного кода в сделанном.
- [ ] Документы и «Журнал» в `PLAN.md` обновлены; в отчёте заказчику честно указано, что не сделано или не проверено.
