# 09. iOS: план и отличия от Android

Обновлено 2026-11-24 (после Android 0.3.2). Этот документ — задание для сессии, которая делает iOS-версию на Mac.

## 0. Как пользоваться

- **Образец поведения — Android-приложение версии 0.5.1** (`android/`). Если документ и код расходятся — прав код.
- Документы `01`–`08` приведены к текущей версии: `01` — экраны и поведение, `03` — календарь, `04` — сервер, `06` — дизайн.
  Как проект менялся по ходу работы — `DECISIONS.md` §5 и `BACKLOG.md` (B-1…B-24); §2 ниже — краткая выжимка.
- Календарные правила (`03-calendar-domain.md` §3–10) и эталонные векторы (`spec/golden/*.json`) общие для всех платформ.
- Работа идёт вехами I0–I9 (§12): тесты → код → проверка в симуляторе → запись в «Журнал» `PLAN.md`.
- Код iOS лежит в `ios/` рядом с `android/`. Android, сайт и сервер из iOS-сессии не менять.

## 4. Стек и структура

- Swift + SwiftUI, без кроссплатформенных фреймворков. Минимальная версия — iOS 17 (SwiftData, String Catalog, Observation).
- Хранение — SwiftData (или SQLite через системный `sqlite3`, если SwiftData не хватит); сеть — `URLSession`.
- Тесты — XCTest / Swift Testing; календарная логика — отдельный Swift-пакет `ios/Domain` без UIKit, чтобы тесты шли быстро.
- Локальная конфигурация (адрес API и публичный ключ) — в `ios/Config.xcconfig`, файл не коммитится; в репозитории — `Config.example.xcconfig`.

## 5. Еврейский календарь

Два пути, оба проверяются одними и теми же векторами — выбрать на I1:
1. перенести арифметику из `hebrew-calendar.js` (не зависит от системы);
2. `Calendar(identifier: .hebrew)` из Foundation.

Если выбран Foundation — нумерация месяцев **другая**, чем в проекте:

| `month` в Foundation | Код проекта |
|---|---|
| 1 | TISHREI |
| 2 | CHESHVAN |
| 3 | KISLEV |
| 4 | TEVET |
| 5 | SHEVAT |
| 6 | ADAR_I (есть только в високосном году) |
| 7 | ADAR (простой год) / ADAR_II (високосный год) |
| 8…13 | NISAN, IYAR, SIVAN, TAMMUZ, AV, ELUL |

- Високосность: `calendar.range(of: .month, in: .year, for: date)!.count == 13`.
- Конвертировать через `DateComponents` в UTC, время — полдень: так исключаются сдвиги из-за пояса и летнего времени.
- Правила годовщин Foundation не знает — реализуются вручную по таблицам B/Y.
- **Первым делом** — тесты на `conversions.json`, `years.json`, `anniversaries.json`. Векторы не править.
- Гематрия (числа буквами для he/yi): 15 → ט״ו, 16 → ט״ז, конечные буквы (ך ם ן ף ץ), тысячи года не пишутся: 5787 → תשפ״ז.

## 6. Заход солнца и сумерки

KosherJava на iOS нет. Порт алгоритма NOAA (≈ 60 строк); геолокация не используется — тот же выбор города.

- Контроль захода (допуск ±6 минут): Иерусалим 21.06.2026 — 19:47, 21.12.2026 — 16:40; Москва — 21:17 и 15:58;
  Нью-Йорк — 20:30 и 16:32. Полярный день (нет захода) → для напоминаний берётся 18:00.
- Выход звёзд — солнце на 8,5° ниже горизонта; если так низко оно не опускается — заход + 72 минуты.
- Подсказка «до или после захода» (`SunsetHints.evaluate` в `Reminders.kt`, тест `sunsetHint` в `DomainTest.kt`):
  до захода → «до»; от захода до выхода звёзд → «сумерки» (переключатель не трогать, показать сомнение);
  позже → «после». После полуночи ещё проверяются сумерки вчерашнего вечера. Захода нет → ответа нет.
- Часовой пояс — исторический: `TimeZone(identifier:)` города на дату события (Москва, апрель 1990 → UTC+4).

## 7. Уведомления и фон

iOS хранит не более 64 ожидающих локальных уведомлений, и приложение не получает управление в момент показа.

1. Планировщик (та же чистая функция) возвращает ближайшие напоминания; у события «по обоим календарям» — для обеих дат.
2. Берутся первые **60**, для каждого — `UNCalendarNotificationTrigger` без повторения.
3. Очередь перестраивается целиком: при запуске и возврате приложения, после каждой правки, после синхронизации
   и в `BGAppRefreshTask` (не чаще раза в сутки; система сама решает, запускать ли).
4. Если 60 уведомлений покрывают меньше ~2 недель — в настройках предупреждение «Открывайте приложение хотя бы раз в N дней».

Идентификатор: `"{eventId}|{occurrenceDate}|{kind}"`. Тексты — как в `NotificationFactory` (`android/.../reminders/Reminders.kt`):
накануне для еврейской даты — «Сегодня вечером: …», для григорианской — «Завтра: …», йорцайт — со строкой про свечу.

Проверка «здоровья» на iOS сводится к разрешению на уведомления и «Фоновому обновлению контента»; кнопка ведёт в настройки
приложения. Экранов про экономию батареи, точные будильники и подсказок по производителям телефонов на iOS нет.
Запрещено то же, что на Android: геолокация, push-сервер, аналитика, постоянные соединения.

## 8. Сервер

`POST https://kalendar.bothub.chat/rest/v1/rpc/<функция>`, заголовки `apikey: <публичный ключ>` и `Content-Type: application/json`,
тело — JSON с именованными параметрами. Другие методы и адреса закрыты. Публичный ключ не секрет, но в репозиторий не кладётся
(на сервере — `/etc/ledor/public-api-key`); его выдаёт заказчик.

Ответ — всегда HTTP 200 и конверт `{"ok": true, …}` либо `{"ok": false, "error": "КОД"}`; у `WRONG_PIN` есть `attempts_left`,
у `LOCKED` — `retry_after_sec`. Коды: `NOT_FOUND, NAME_TAKEN, INVALID_NAME, INVALID_PIN, PINS_EQUAL, WRONG_PIN, LOCKED,
RATE_LIMITED, UNAUTHORIZED, FORBIDDEN, LIST_DELETED, INVALID_EVENT, FOREIGN_ID, BATCH_TOO_LARGE, FEEDBACK_EMPTY, FEEDBACK_TOO_LONG`.

| Функция | Параметры |
|---|---|
| `list_exists` | `p_name` |
| `create_list` | `p_name, p_read_pin, p_master_pin` |
| `join_list` | `p_name, p_pin` (обычный ПИН → READER, мастер-ПИН → EDITOR) |
| `pull_changes` | `p_list_id, p_token, p_since` |
| `push_events` | `p_list_id, p_token, p_events` (до 500 за раз) |
| `leave_list` | `p_list_id, p_token` |
| `delete_list` | `p_list_id, p_token, p_master_pin` |
| `submit_feedback` | `p_message, p_contact, p_meta` (`app_version, device, os_version, locale`) |

Точные поля события и логика синхронизации — `supabase/migrations/*.sql`, `android/.../data/remote/SupabaseRpc.kt`,
`android/.../data/repo/Repositories.kt` (`SyncEngine`). Проверка сервера — `tools/rpc-smoke/smoke.mjs`
(14 сценариев; запускать не чаще 5 раз в час — лимит на создание списков). Свои тестовые списки удалять за собой.

## 9. Экраны и тексты

Те же экраны, что на Android (`android/app/src/main/java/org/ledor/ui/`); снимки всех экранов на всех языках —
`./gradlew :app:recordRoborazziDebug` → `android/app/build/screens/<язык>/`.

Заставка · диалог импорта при первом запуске · календарь (две сетки, ближайшие события) · события (две вкладки, фильтр по
спискам, прошедшие) · карточка события · редактор (тип, повтор, дата в любом календаре, «год неизвестен», до/после захода
и подсказка, «отмечать по…», заметка, ближайшая дата) · конвертер · списки (личный и общие; создание с двумя ПИН-кодами,
подключение, ПИН-коды, «Поделиться» в Telegram/WhatsApp/другое, синхронизация, отключение, удаление) · настройки
(два напоминания, город, первый день недели, тема, обычай для Адара) · отзыв · «О программе» · «Ещё».

- **Тексты не переводить заново**: перенести из `strings.xml` в String Catalog скриптом (папки `values` → en, `values-ru`,
  `values-iw` → he, `values-ji` → yi, `values-fr`, `values-es`), включая формы множественного числа.
  he, yi, fr, es — машинный перевод, ждёт вычитки носителем; правки вносить сразу в обе платформы.
- Выбор языка на iOS — системный («Настройки → LeDor → Язык»); в настройках приложения — строка, которая туда ведёт.
- «Поделиться»: `https://t.me/share/url?url=…&text=…`, `https://wa.me/?text=…` и системный `ShareLink`; текст приглашения —
  строка `share_message`.

## 10. Чего на iOS не будет или будет иначе

| Android | iOS |

| экран про экономию батареи, подсказки Samsung/Xiaomi… | нет |
| WorkManager, приёмник перезагрузки | `BGAppRefreshTask`, перестройка очереди при открытии |
| переключатель языка в настройках | системный язык приложения |
| «Android 8.0 и новее», APK | App Store / TestFlight |

## 11. App Store

- Нужен Apple Developer Program (заказчик). До него — только симулятор.
- Перед выпуском — проверка на настоящем iPhone (уведомления, фон), хотя бы через TestFlight у знакомых.
- Политика конфиденциальности: `https://kalendar.bothub.chat/<lang>/privacy/`. В ней сейчас упоминается только Android
  (удаление данных, резервные копии) — перед выпуском дополнить про iOS и iCloud (правится в `tools/site/i18n/*.mjs`,
  это делает сессия на сервере).
- «Этикетки конфиденциальности»: пользовательское содержимое (общие списки) и необязательный контакт в отзыве —
  не привязаны к личности; трекинга и рекламы нет.
- Шифрование — только системный HTTPS: `ITSAppUsesNonExemptEncryption = NO`.
- Для проверяющих Apple — в заметках к версии дать название и ПИН тестового общего списка.
- Требования магазинов — `08-store-compliance.md`.

## 14. Еврейские праздники (добавлено в Android 0.5.0)

Встроенный список «Еврейские праздники» — `01` §3.13, правила и таблица дат — `03` §12, напоминания — `05` §9.
На iOS: правила праздников и зажигания свечей пишутся в пакете `Domain` и проверяются на `spec/golden/holidays.json` и
`candles.json` (в Foundation праздников нет). Имена `Holiday` — те же. Напоминания — только накануне вечером; при лимите
в 64 уведомления праздники и Шабат планируются вместе с событиями в общем порядке по времени. Названия праздников —
в ресурсах на шести языках (взять из `android/app/src/main/res/values*/strings.xml`, ключи `holiday_*`).
