# 08. Требования магазинов приложений

Правила магазинов меняются. Перед отправкой на проверку свериться с актуальными страницами
Google Play Console Help и App Store Review Guidelines; этот документ — чек-лист, а не источник истины.
Состояние на 2026-11-24: приложение раздаётся как APK с сайта, в магазинах не опубликовано.

## 1. Google Play — что должно быть готово

| Требование | Чем закрываем | Состояние |
|---|---|---|
| Политика конфиденциальности (публичный URL + ссылка внутри приложения) | `https://kalendar.bothub.chat/<lang>/privacy/`, ссылка в «О программе» | есть |
| Способ запросить удаление данных | удаление списка внутри приложения; раздел `#delete` политики; обращения — через «Отправить отзыв» | есть |
| Контакты разработчика | Google требует публичную почту поддержки — **её пока нет** (на сайте только канал и форма отзыва) | нужна почта |
| Аккаунт разработчика, имя разработчика | заказчик | нет |
| Целевой уровень API | `targetSdk = 36`; проверить требование на дату публикации | есть |
| Формат и подпись | App Bundle (`.aab`), Play App Signing. **Сейчас release подписывается отладочным ключом** — нужен постоянный ключ загрузки; после смены ключа установленные с сайта копии придётся переустановить | не сделано |
| Возрастной рейтинг | анкета: нет насилия, азартных игр и т. п.; есть пользовательское содержимое внутри закрытых списков | не заполнено |
| Раздел «Безопасность данных» | ответы в §2 | не заполнено |
| Декларация точных будильников | §3 | не заполнено |
| Страница приложения | §6 | не готово |
| Тестирование перед выходом | для новых личных аккаунтов Google требует закрытое тестирование (по состоянию на 2025 год — не менее 12 человек в течение 14 дней; уточнить в консоли) | не начато |

## 2. Раздел «Безопасность данных» (Data safety)

| Вопрос | Ответ |
|---|---|
| Собирает ли приложение данные? | Да — содержимое общих списков, которое пользователь сам вводит и синхронизирует, и отзывы, которые он сам отправляет |
| Какие типы | «Личная информация → Имя» (имена людей в событиях), «Другой пользовательский контент» (даты, названия, заметки, текст отзыва); по желанию пользователя — контакт для ответа и сведения об устройстве (модель, версия Android, версия приложения, язык) |
| Передаются ли третьим лицам? | Нет. Сервер свой; отзывы пересылаются автору через Telegram |
| Обязателен ли сбор? | Нет: приложение полностью работает с личным списком без сервера, отзыв и техданные — по желанию |
| Цель | Функциональность приложения; связь с разработчиком |
| Шифрование при передаче | Да (HTTPS) |
| Можно ли запросить удаление | Да — внутри приложения (удаление списка) и через форму отзыва; отзывы хранятся не дольше 2 лет |
| Геолокация, контакты, рекламный идентификатор, аналитика | Не собираются |

## 3. Чувствительные разрешения

| Разрешение | Обоснование | Запасной вариант, если Google отклонит |
|---|---|---|
| `USE_EXACT_ALARM` | Приложение — календарь, показывающий уведомления о событиях; это прямо разрешённый политикой сценарий. В декларации: «календарное приложение с напоминаниями о событиях в заданное пользователем время». | Убрать `USE_EXACT_ALARM`, оставить `SCHEDULE_EXACT_ALARM` без `maxSdkVersion`. Код менять не нужно: проверка `canScheduleExactAlarms()` и переход в настройку уже есть. |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | **Риск:** проверка кода (lint, `BatteryLife`) предупреждает, что прямой запрос нарушает правила Google Play. | **До публикации убрать разрешение из манифеста.** Кнопка «Исправить» начнёт открывать общий список оптимизации батареи / карточку приложения (цепочка откатов уже реализована). |
| `POST_NOTIFICATIONS` | Стандартный запрос. | — |
| `RECEIVE_BOOT_COMPLETED` | Восстановление напоминаний после перезагрузки. | — |

## 4. Пользовательское содержимое и модерация

Списки закрыты ПИН-кодом и не публикуются, но содержимое создают пользователи, поэтому:

- у каждого общего списка есть «Пожаловаться на список» — открывает форму отзыва с названием списка;
- владелец может удалить список с сервера целиком (Мастер-ПИН);
- любой участник может отключить список от своего телефона;
- у автора есть техническая возможность удалить список по обоснованной жалобе (SQL на сервере — `supabase/README.md`).

| Требование | Чем закрываем |

## 6. Страница приложения в магазине

- Название до 30 знаков: бренд + ключевые слова, как у лидеров выдачи по «hebrew calendar» (например, «LeDor: Hebrew Birthdays & Yahrzeit»);
  краткое описание до 80, полное до 4000 — на шести языках.
- Ключевые мысли: напоминает о днях рождения и йорцайтах накануне вечером и в день события; списком легко поделиться
  с семьёй или общиной — без регистрации; два календаря, йорцайт и бар/бат-мицва считаются правильно, включая Адар I / II;
  не расходует батарею; бесплатно, без рекламы, открытый код.
- Чем отличаемся от конкурентов (HebDate, Hebrew Calendar & Zmanim Luach и др.): нет рекламы и платного контента; общие
  списки по ПИН-коду с ролями; напоминание относительно заката; фокус на семейных датах, а не на зманим и сидуре.
- Графика: значок 512×512, обложка 1024×500, снимки экрана — из `android/app/build/screens/<язык>/`.
- Не использовать слова «лучший», «№1», чужие торговые марки и названия других приложений.
