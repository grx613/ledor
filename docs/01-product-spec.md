# 01. Техническое задание: продукт и экраны

Рабочее название приложения — **Kalendar** (окончательное название — вопрос Q-01).
Разработчик — **BotHub FiRe**. Приложение некоммерческое, с открытым исходным кодом.

## 1. Что это

Мобильное приложение-напоминалка о днях рождения, йорцайтах (годовщинах памяти) и семейных событиях с поддержкой
еврейского и григорианского календарей. Списки событий можно вести локально или делить с семьёй/общиной через облако.

**Порядок работ:** сначала Android (этот документ), попутно сайт разработчика; iOS — следующим этапом
(`09-ios-notes.md`).

### Не делаем (осознанно)

- Экспорт в Google Calendar / Samsung Calendar и любые внешние календари.
- Учётные записи, регистрацию, вход по почте/телефону.
- Фоновую геолокацию и геолокацию вообще.
- Кроссплатформенные фреймворки (Flutter, React Native, Compose Multiplatform UI).
- Рекламу, аналитику, трекеры, push-серверы.

### Приоритеты

- **[P1]** — обязательно для первой версии (всё из исходного задания заказчика).
- **[P2]** — улучшение, делается только после того, как все P1 готовы и приняты. Если пометки нет — это P1.

## 2. Понятия

| Понятие | Описание |
|---|---|
| Личный список | Существует всегда, хранится только на телефоне, не синхронизируется. |
| Облачный список | Хранится в Supabase, находится по **названию**, открывается **ПИН-кодом**. |
| Обычный ПИН | Только чтение: просмотр событий и уведомления. 4–8 цифр. |
| Мастер-ПИН | Чтение и запись: добавление, изменение, удаление событий и удаление списка из облака. 6–12 цифр. |
| Роль на устройстве | `Личный` / `Чтение` / `Редактор` — определяется тем, каким ПИНом подключили список. |
| Событие | Имя/название + тип + дата + календарь, по которому оно отмечается. |

Количество подключённых списков не ограничено (семья, родственники, коллеги, синагога…).

## 3. Экраны

### 3.1. Заставка (Splash) — `SPL`

- **SPL-1.** При холодном запуске мгновенно показывается системная заставка (иконка приложения на фирменном фоне),
  затем — брендовая: логотип **BotHub FiRe** (`assets/brand/bothub-fire-logo.svg`) и надпись «BotHub FiRe».
- **SPL-2.** Длительность брендовой заставки — 1500 мс (константа `SPLASH_DURATION_MS`), плавное исчезновение 250 мс.
  За это время открывается база и готовятся данные календаря.
- **SPL-3.** При возврате в уже запущенное приложение и при повороте экрана заставка не показывается.

### 3.2. Окно импорта при первом запуске — `ONB`

- **ONB-1.** После заставки, только при самом первом запуске, поверх календаря — диалог:
  - Заголовок: «Хотите импортировать список дней рождения?»
  - Текст: «Если у вашей семьи или общины уже есть список, введите его название и ПИН-код.»
  - Кнопки: **Да**, **Нет**, крестик **✕** в углу.
- **ONB-2.** «Да» → экран «Подключить список» (§3.9.3). После успешного импорта — календарь с сообщением
  «Импортировано событий: N».
- **ONB-3.** «Нет», ✕, системная кнопка «Назад», нажатие мимо диалога → диалог закрывается, открыт календарь;
  приложением можно пользоваться локально, список можно подключить/создать позже.
- **ONB-4.** Диалог больше никогда не появляется (флаг ставится при любом исходе).

### 3.3. Главный экран: календарь — `CAL`

Нижняя панель навигации: **Календарь · События · Конвертер · Ещё**.

- **CAL-1.** Сетка месяца, 7 колонок. В каждой ячейке — **обе даты**: основная (крупно) и дата второго календаря
  (мелко). На 1-е число второго календаря мелким шрифтом пишется сокращение месяца («1 Тев»).
- **CAL-2.** Заголовок: «Ноябрь 2026 · Хешван – Кислев 5787». Листание месяцев свайпом и стрелками; кнопка «Сегодня».
- **CAL-3.** Переключатель основы сетки: **григорианские месяцы / еврейские месяцы**. Во втором режиме ячейки
  идут по дням еврейского месяца, крупно — еврейский день, мелко — григорианский.
- **CAL-4.** Отметки событий в ячейке: до трёх цветных точек (цвет по типу события), при большем числе — «+N».
  Сегодняшний день обведён контуром Маген Давида; выбранный день — заливка. Колонка субботы слегка тонирована.
- **CAL-5.** Неделя начинается с воскресенья (настройка «Первый день недели»: воскресенье/понедельник).
- **CAL-6.** Под сеткой — блок **«Ближайшие события»**: ближайшие наступления на 30 дней вперёд (не меньше 5 штук,
  если события есть). Строка: значок типа, имя, тип, дата в обоих календарях, «сегодня / завтра / через N дней»,
  возраст («исполняется 37»), метка списка.
- **CAL-7.** Нажатие на день: блок под сеткой превращается в «События {дата}» + кнопка «Добавить на эту дату»
  (открывает редактор с подставленной датой). Повторное нажатие/«Сегодня» возвращает «Ближайшие события».
- **CAL-8.** Плавающая кнопка **«+»** — добавить событие. В верхней панели — кнопка **«Списки»** (переход к управлению списками).
- **CAL-9.** Над сеткой при необходимости — баннер о разрешениях (`05-reminders-battery.md` §5.1) и одноразовые
  сообщения («Список „X“ удалён владельцем»).
- **CAL-10.** Пустое состояние (нет событий): иллюстрация с Маген Давидом, текст «Пока нет событий. Добавьте первое —
  день рождения, йорцайт или семейный праздник.», кнопки «Добавить событие» и «Подключить список».

Для событий по еврейскому календарю, наступающих завтра, пишется «завтра (начинается сегодня вечером)».

### 3.4. Добавление и редактирование события — `EVT`

Открывается кнопкой «+», из карточки события («Изменить»), из конвертера и из дня календаря.

Поля сверху вниз:

1. **EVT-1. «Имя или название»** — одно текстовое поле (без деления на имя и фамилию). Обязательное, до 120 символов.
2. **EVT-2. «Список»** — выпадающий выбор: «Личный» и все подключённые списки с ролью «Редактор».
   Списки «только чтение» не показываются. По умолчанию — последний использованный.
3. **EVT-3. «Тип события»** — шесть вариантов (чипы со значками): День рождения · Йорцайт · Бар-мицва · Бат-мицва ·
   Свадьба · Другое. При выборе «Другое» появляется поле **«Название события»** (обязательное, до 60 символов).
4. **EVT-4. Переключатель «Повторяется каждый год»** (выключен = одноразовое событие). Выставляется автоматически по типу:
   день рождения, йорцайт, свадьба, другое — включён; бар-мицва, бат-мицва — выключен. Если пользователь
   переключил вручную, последующая смена типа его выбор не сбрасывает.
5. **EVT-5. Дата.** Сегмент «Григорианская дата | Еврейская дата» — в каком календаре вводим.
   - Григорианская: День, Месяц, Год + флажок «Год неизвестен». При известном годе — переключатель
     **«До захода солнца / После захода солнца»** (по умолчанию «до»).
   - Еврейская: День (1–30), Месяц, Год + флажок «Год неизвестен». Если год указан — в списке месяцев только
     месяцы этого года (Адар **или** Адар I и Адар II), порядок от Тишрея; если нет — все 14 вариантов.
     Недопустимый день (30-е в 29-дневном месяце) подсвечивается ошибкой «В этом месяце 29 дней».
6. **EVT-6. Карточка перевода (обновляется мгновенно при любом изменении):**
   - введена григорианская → «Еврейская дата: **28 Нисана 5750**» (с учётом переключателя захода);
   - введена еврейская → «Григорианская дата: **понедельник, 23 апреля 1990**. Еврейский день начинается накануне
     вечером, с заходом солнца 22 апреля».
   - год не указан → «Укажите год, чтобы увидеть перевод даты».
7. **EVT-7. «Отмечать каждый год»** (только для повторяющихся): два варианта с конкретными датами —
   «По еврейскому календарю — 28 Нисана» / «По григорианскому календарю — 23 апреля».
   По умолчанию — по еврейскому. Если год не указан, доступен только календарь ввода, второй вариант
   неактивен с подсказкой «Нужен год рождения».
   Под выбором — строка «Ближайшее: ср, 5 мая 2027 (28 Нисана 5787) — через 162 дня, исполнится 37».
8. **EVT-8. Подсказка о бар/бат-мицве** — только для типа «День рождения» с известным годом и только если дата ещё
   не наступила (пример для родившегося 2 июня 2015 = 15 Сивана 5775):
   «Бар-мицва (13 лет): 15 Сивана 5788 — пт, 9 июня 2028» **[Добавить событие]**
   «Бат-мицва (12 лет): 15 Сивана 5787 — вс, 20 июня 2027» **[Добавить событие]**
   Пол не спрашиваем — показываются обе строки, пользователь выбирает нужную. Кнопка сразу создаёт в том же списке одноразовое событие соответствующего типа с тем же именем и показывает
   «Событие добавлено».
9. **EVT-9. «Заметка»** — необязательное многострочное поле, до 500 символов.
10. **EVT-10.** Кнопки: **Сохранить**; в режиме редактирования — **Удалить** (с подтверждением «Удалить событие „X“?»).
    «Назад» при несохранённых изменениях → «Сохранить изменения? Сохранить / Не сохранять / Отмена».

- **EVT-11.** Сохранение мгновенное и не зависит от сети: в облачный список событие отправляется в фоне;
  пока не отправлено — у события значок «ожидает отправки».
- **EVT-12.** Смена списка у существующего события = перенос в другой список.

### 3.5. Карточка события — `DET`

- **DET-1.** Открывается нажатием на событие где угодно и из уведомления. Показывает: значок и тип, имя, обе даты
  (исходные), по какому календарю отмечается, ближайшее наступление и «через N дней», возраст/сколько лет, год
  рождения, заметку, список, подсказку о бар/бат-мицве (как EVT-8).
- **DET-2.** Кнопки «Изменить» и «Удалить» — только при праве записи. Для списков «только чтение» — надпись
  «Список только для чтения».

### 3.6. Список всех событий — `ALL`

- **ALL-1.** Все события одним списком сверху вниз, отсортированы по ближайшему наступлению начиная с сегодня.
- **ALL-2.** Две вкладки: **«Еврейский календарь»** и **«Григорианский календарь»**. Вкладка определяет, в каком
  календаре показаны даты и по месяцам какого календаря сгруппирован список (заголовки «Кислев 5787» / «Декабрь 2026»).
  На обеих вкладках — все события (трактовка зафиксирована как допущение A-1 в `DECISIONS.md`).
- **ALL-3.** Строка: значок типа · имя/название · тип (для «Другое» — своё название) · дата во «вкладочном» календаре
  крупно и во втором мелко · год рождения/исходный год, если известен · «исполняется N» · «через N дней» ·
  значок, по какому календарю событие отмечается (✡ — еврейский, ◯ — григорианский) · цветная метка списка.
- **ALL-4.** Фильтр по спискам: чипы «Все списки» + по одному на каждый подключённый список (одиночный выбор).
- **ALL-5.** Прошедшие одноразовые события — в свёрнутой секции «Прошедшие» в конце.
- **ALL-6.** Кнопка «+» и кнопка «Списки» — как на календаре. Пустое состояние — как CAL-10.
- **ALL-7. [P2]** Поиск по имени.

### 3.7. Конвертер дат — `CNV`

- **CNV-1.** Сегмент «Григорианская → Еврейская | Еврейская → Григорианская».
- **CNV-2.** Григорианская → еврейская: выбор даты + переключатель «До захода солнца / После захода солнца» →
  результат «28 Нисана 5750», день недели. По умолчанию — сегодняшняя дата.
- **CNV-3.** Еврейская → григорианская: День, Месяц (по году), Год → «понедельник, 23 апреля 1990» и пояснение
  «Еврейский день начинается накануне вечером, с заходом солнца 22 апреля».
- **CNV-4.** Кнопка **«Создать событие на эту дату»** → редактор с подставленными календарём ввода, датой и
  признаком захода.
- **CNV-5. [P2]** Под результатом: «Если это дата рождения: Бар-мицва … / Бат-мицва …» и
  «Если это дата смерти: ближайший йорцайт …».

### 3.8. «Ещё»

Список пунктов: **Управление списками**, **Настройки**, **О программе**.

### 3.9. Управление списками — `LST`

#### 3.9.1. Экран списков
- **LST-1.** Карточка на каждый список: название, роль (Личный / Чтение / Редактор), число событий, время последней
  синхронизации, цветная метка, переключатель «Уведомления» (выключить напоминания по этому списку).
  Состояние «Нет доступа» — предупреждающая метка.
- **LST-2.** Кнопки: **«Создать список»**, **«Подключить список»**. Потянуть вниз — синхронизировать всё.

#### 3.9.2. Создать список
- **LST-3.** Поля: «Название списка» (3–60 символов; проверка занятости на лету, с задержкой 500 мс: «Название
  свободно ✓» / «Такой список уже есть»), «ПИН-код для чтения» (4–8 цифр, предзаполнен случайными 6 цифрами),
  «Мастер-ПИН для редактирования» (6–12 цифр, предзаполнен случайными 8 цифрами), кнопки «Сгенерировать заново».
  Пояснение: «Обычный ПИН дайте тем, кто будет только смотреть. Мастер-ПИН — только тем, кому доверяете изменять список.»
- **LST-4.** Флажок «Перенести события из личного списка» (показывается, если в личном есть события).
- **LST-5.** «Создать» (нужен интернет) → экран списка с предложением поделиться.

#### 3.9.3. Подключить (импортировать) список
- **LST-6.** Шаг 1: «Название списка» → «Найти». Не найден → «Список не найден. Проверьте название.»
- **LST-7.** Шаг 2 (список найден): «ПИН-код» → «Подключить». Подойдёт и обычный ПИН, и Мастер-ПИН — роль
  определится автоматически. Ошибки: «Неверный ПИН-код. Осталось попыток: N», «Слишком много неверных попыток.
  Попробуйте через N минут», «Нет соединения с интернетом».
- **LST-8.** Успех → события загружены, сообщение «Импортировано событий: N», роль показана.
- **LST-9.** Повторное подключение уже подключённого списка не создаёт дубль, а обновляет роль (так «читатель»
  становится «редактором», введя Мастер-ПИН).

#### 3.9.4. Экран одного списка
- **LST-10. ПИН-коды:** сохранённые коды скрыты точками, кнопка-глаз показывает, кнопка «Копировать».
  Обычный ПИН виден всем; Мастер-ПИН — только если он сохранён на этом телефоне.
- **LST-11. Поделиться:** кнопки **Telegram**, **WhatsApp**, **Другое…** (системное меню). Отправляется готовое сообщение:

  ```
  📅 Список «{название}» в приложении {AppName}: дни рождения, йорцайты и семейные события
  по еврейскому и обычному календарю.

  1. Установите приложение: {ссылка}
  2. Откройте «Списки» → «Подключить список»
  3. Название: {название}
  4. ПИН-код: {пин}
  ```

  По умолчанию отправляется обычный ПИН. Редактор может выбрать «Поделиться правом редактирования» — тогда
  отправляется Мастер-ПИН, перед этим предупреждение: «Мастер-ПИН позволяет изменять и удалять события и весь
  список. Отправляйте его только тем, кому полностью доверяете.»
  Telegram: `https://t.me/share/url?url={ссылка}&text={текст}`; WhatsApp: `https://wa.me/?text={текст}` —
  через `ACTION_VIEW`, с откатом на системное меню, если нечем открыть.
- **LST-12.** «Синхронизировать сейчас»; «Ввести Мастер-ПИН» (для читателя).
- **LST-13. «Отключить список от этого телефона»** — подтверждение «События списка исчезнут с этого телефона.
  В облаке список останется.»
- **LST-14. «Удалить список из облака»** — только для редактора. Требует ввести Мастер-ПИН ещё раз и подтвердить:
  «Список и все его события будут удалены безвозвратно у всех участников.» Нужен интернет.
  (Обязательное требование магазинов приложений.)
- **LST-15.** «Пожаловаться на список» — письмо на адрес поддержки с названием списка в теме.
- **LST-16.** Личный список: нельзя отключить/удалить; есть действие «Перенести события в облачный список…».
- **LST-17.** Если список удалён владельцем — при следующей синхронизации он исчезает с телефона, на главном экране
  одноразовое сообщение «Список „X“ удалён владельцем».

### 3.10. Настройки — `SET`

- **SET-1. Первое напоминание (накануне вечером):** включено/выключено; режим «За … до захода солнца»
  (0–6 часов, шаг 30 минут, по умолчанию **3 часа**) или «В фиксированное время» (по умолчанию 15:00).
- **SET-2. Второе напоминание (в день события):** включено/выключено; время (по умолчанию **12:00**).
- **SET-3. Город для расчёта захода солнца:** «Не выбран — заход считается в 18:00» → экран выбора города с поиском
  (на трёх языках). Без запроса геолокации.
- **SET-4.** Предпросмотр: «Сегодня заход солнца в 16:36 → напоминание накануне придёт в 13:36».
- **SET-5. Надёжность напоминаний:** четыре пункта со статусом и кнопками исправления, переключатель «Показывать
  предупреждения», «Отправить тестовое уведомление» (`05-reminders-battery.md` §5).
- **SET-6. Вид:** первый день недели; тема (как в системе / светлая / тёмная).
- **SET-7. [P2]** Йорцайт в високосный год для умерших в Адар простого года: «Адар I (ашкеназский обычай)» /
  «Адар II (сефардский обычай)». **[P2]** Еврейские числа буквами (א׳, ב׳…).

### 3.11. О программе — `ABT`

- **ABT-1.** Логотип и название **BotHub FiRe**, название приложения и версия.
- **ABT-2.** Текст: «Приложение некоммерческое и бесплатное. В нём нет рекламы и сбора данных. Исходный код открыт
  (Open Source) — любой может проверить, как оно работает, и предложить улучшения.»
- **ABT-3.** Ссылки: «Исходный код на GitLab», «Сайт разработчика», «Политика конфиденциальности», «Написать нам».
- **ABT-4.** «Лицензии открытого ПО»: KosherJava Zmanim (LGPL 2.1), шрифт Rubik (OFL 1.1), OkHttp, AndroidX, Kotlin (Apache 2.0).
