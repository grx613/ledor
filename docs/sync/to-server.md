## M-1 · 2026-11-26 · Ответ на S-1: 0.6.3 в Google Play и те же исправления в iOS

Статус: открыто

**Google Play.** 0.6.1 к этому моменту уже прошёл проверку, новый выпуск консоль создать дала. `ledor-0.6.3.aab` скачан
(5 921 613 байт), загружен в Closed testing (Alpha): консоль показала **12 (0.6.3)**, замечаний к подписи нет, название
«12 (0.6.3)», примечания на 5 языках из S-1. Ошибок нет; одно предупреждение — нет файла отладочных символов (как у 0.6.0 и
0.6.1); поддерживаемые устройства не изменились (11 530 телефонов). Выпуск сохранён, в «Обзоре публикации» ровно 1 изменение
(Alpha, 12 (0.6.3)). Заказчик отправил его на проверку Google («Изменения на проверке», 2026-11-26). Во внутреннее
тестирование 0.6.3 не добавлял.

**iOS — пункты раздела 3:**
1. Две строки для «по обоим» — сделано: `OccurrenceCalculator.nextEach` в `ios/Domain` (тест как `DomainTest.observeBoth`:
   24.11.2026 → 23.04.2027 и 05.05.2027; 24.04.2027 → 05.05.2027 и 23.04.2028); «Ближайшие» и «События» строят строки по
   `nextEach`, ключ строки — id события + дата.
2. У григорианской даты — только григорианская: `Formatters.occurrenceDates` / `occurrenceDatesInline`, как
   `DateFormatters` на Android; строка события, карточка, редактор.
3. Карточка — два блока «По григорианскому / По еврейскому календарю», каждый со своей датой, «через N дней» и возрастом.
4. Редактор — «Ближайшее» по строке на каждую дату; строка `next_occurrence` взята новая (2 аргумента) из `strings.xml`
   скриптом `ios/tools/strings.py`.
5. Уведомление «в день события» — у григорианского наступления только «{григорианская дата}. {возраст}».
6. Перенос личного списка (B-27) — кнопка видна всегда при событиях; без облачных списков открывает «Создать список» с
   включённым переносом; есть — меню: списки и «+ Создать список»; после переноса и после создания открывается экран списка.
7. D-45 к iOS не относится — не трогал.
