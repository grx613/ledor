# 08. Требования магазинов приложений

Правила магазинов меняются. Перед отправкой на проверку свериться с актуальными страницами
Google Play Console Help и App Store Review Guidelines; этот документ — чек-лист, а не источник истины.

## 1. Google Play — что должно быть готово

| Требование | Чем закрываем |
|---|---|
| Политика конфиденциальности (публичный URL + ссылка внутри приложения) | `website/privacy/`, ссылка в «О программе» |
| Адрес для запроса удаления данных | `website/delete-data/` + удаление списка из облака внутри приложения |
| Контакты разработчика (почта, сайт) | `website/support/`, почта поддержки (Q-05) |
| Целевой уровень API | `targetSdk = 36`; проверить актуальное требование на дату публикации |
| Формат | Android App Bundle (`.aab`), подпись Play App Signing |
| Возрастной рейтинг | анкета: нет насилия, азартных игр и т. п.; есть обмен пользовательским содержимым внутри закрытых списков |
| Раздел «Безопасность данных» | ответы в §2 |
| Декларация точных будильников | §3 |
| Описание, снимки экрана, значок 512×512, графика 1024×500 | `docs/store/` — готовится в вехе M15 |
| Тестирование перед выходом | для новых личных аккаунтов разработчика Google требует закрытое тестирование (число тестировщиков и срок — уточнить в Play Console на момент публикации) |

## 2. Раздел «Безопасность данных» (Data safety)

| Вопрос | Ответ |
|---|---|
| Собирает ли приложение данные? | Да — только содержимое облачных списков, которое пользователь сам вводит и синхронизирует |
| Какие типы | «Личная информация → Имя» (имена людей в событиях) и «Другой пользовательский контент» (даты, названия, заметки) |
| Передаются ли третьим лицам? | Нет (Supabase — обработчик по поручению, а не третья сторона-получатель) |
| Обязателен ли сбор? | Нет: приложение полностью работает с личным списком без облака |
| Цель | Функциональность приложения |
| Шифрование при передаче | Да (HTTPS) |
| Можно ли запросить удаление | Да — внутри приложения и по адресу `delete-data/` |
| Геолокация, контакты, рекламный идентификатор, аналитика | Не собираются |

## 3. Чувствительные разрешения

| Разрешение | Обоснование | Запасной вариант, если Google отклонит |
|---|---|---|
| `USE_EXACT_ALARM` | Приложение — календарь, показывающий уведомления о событиях; это прямо разрешённый политикой сценарий. В декларации указать: «календарное приложение с напоминаниями о событиях в заданное пользователем время». | Убрать `USE_EXACT_ALARM`, оставить `SCHEDULE_EXACT_ALARM` без `maxSdkVersion`. Код менять не нужно: проверка `canScheduleExactAlarms()` и переход в настройку уже есть. |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Напоминание в точное время — основная функция; на ряде устройств без исключения из оптимизации уведомления не приходят. Запрос показывается только по нажатию пользователя, с объяснением, и его можно отключить навсегда. | Убрать разрешение из манифеста. Кнопка автоматически начнёт открывать общий список оптимизации батареи / карточку приложения (цепочка откатов уже реализована). |
| `POST_NOTIFICATIONS` | Стандартный запрос; спрашивать не при первом запуске, а при первом сохранении события или по кнопке из баннера. | — |
| `RECEIVE_BOOT_COMPLETED` | Восстановление напоминаний после перезагрузки. | — |

Оба запасных варианта — правка манифеста в одну строку; описать их в `android/README.md`.

## 4. Пользовательское содержимое и модерация

Списки закрыты ПИН-кодом и не публикуются, но содержимое создают пользователи, поэтому:

- у каждого облачного списка есть «Пожаловаться на список» (письмо в поддержку);
- владелец может удалить список из облака целиком (Мастер-ПИН);
- любой участник может отключить список от своего телефона;
- в описании приложения и в политике указан адрес для жалоб; заявленный срок реакции — до 3 рабочих дней;
- у разработчика есть техническая возможность удалить список по обоснованной жалобе (SQL в панели Supabase;
  порядок действий описать в `supabase/README.md`).

## 5. App Store (понадобится на этапе iOS)

| Требование | Чем закрываем |
|---|---|
| Privacy Policy URL, Support URL | `privacy/`, `support/` |
| «Этикетки конфиденциальности» | User Content + Name; не связаны с личностью, не используются для отслеживания |
| 1.2 Пользовательский контент | жалоба на список, удаление списка, контакты — см. §4 |
| 5.1.1 Удаление данных | учётных записей нет; удаление списка — внутри приложения |
| 4.2 Минимальная функциональность | полноценное нативное приложение, не веб-обёртка |
| Уведомления | локальные (`UNUserNotificationCenter`), без push-сервера |
| Фон | `BGAppRefreshTask`, идентификатор задачи в `Info.plist` |
| Шифрование (export compliance) | только стандартный HTTPS → `ITSAppUsesNonExemptEncryption = NO` |

## 6. Тексты для страницы приложения (готовятся в M15)

- Название (до 30 знаков), краткое описание (до 80), полное описание (до 4000) — на русском и английском.
- Ключевые мысли: два календаря; йорцайт и бар/бат-мицва считаются правильно, включая Адар I / Адар II;
  общие списки для семьи и общины; напоминание накануне вечером и в день события; не расходует батарею;
  бесплатно, без рекламы, открытый исходный код.
- Не использовать в названии и описании слова «лучший», «№1», чужие торговые марки и названия других приложений.
