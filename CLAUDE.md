# Kalendar — правила для исполнителя

Нативное приложение-напоминалка о днях рождения, йорцайтах и семейных событиях по еврейскому и григорианскому
календарям + сайт разработчика. Разработчик — BotHub FiRe. Общение с заказчиком — на русском.

Проект полностью спроектирован заранее. Твоя задача — реализовывать вехи из `docs/PLAN.md` строго по документам.

## С чего начинать сессию

1. Открой `docs/PLAN.md`, найди свою веху.
2. Прочитай только документы из её строки «Читать». Не читай всё подряд.
3. Работай в порядке: тесты → код → проверка → чекбоксы и «Журнал» в `PLAN.md`.

| Документ | О чём |
|---|---|
| `docs/01-product-spec.md` | экраны, поведение, точные тексты (идентификаторы требований CAL-1, EVT-4 …) |
| `docs/02-architecture.md` | стек и версии, модули, пакеты, схема Room, навигация, тестирование |
| `docs/03-calendar-domain.md` | еврейский календарь, правила годовщин, API KosherJava 3.1, планировщик |

## Команды

```bash
source tools/env.sh                                   # JAVA_HOME, ANDROID_HOME (создаётся в M0)
cd android && ./gradlew :domain:test                  # быстрые тесты логики
cd android && ./gradlew :domain:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug   # полная проверка
cd android && ./gradlew :app:recordRoborazziDebug     # снимки экранов → app/build/outputs/roborazzi/
node --test website/tests/*.test.mjs                          # тесты конвертера сайта
node tools/site/build.mjs                             # собрать страницы сайта из tools/site/i18n/*.mjs
tools/deploy/publish.sh                               # выложить website/ на kalendar.bothub.chat
cd tools/golden && npm ci && node generate.mjs        # пересоздать эталонные векторы (обычно не нужно)
```

## Нерушимые правила

1. **Только натив.** Android — Kotlin + Jetpack Compose. Никаких Flutter, React Native, Compose Multiplatform, WebView-экранов.
2. **Батарея.** Запрещены: foreground-сервисы, wake lock'и, геолокация, Firebase/FCM/Play Services, аналитика,
   WebSocket/Realtime, `setRepeating`, фоновые задачи чаще раза в сутки. Подробно — `05-reminders-battery.md` §1.
3. **Календарь — только через тесты.** Любой код, считающий еврейские даты, сначала получает тест на
   `spec/golden/*.json`. KosherJava вызывается только из `HebrewCalendarMath` и `CitySunsetProvider`.
4. **KosherJava — версия 3.1.0, API на `java.time`.** То, что ты помнишь про `JewishDate(Date)` / `Calendar`, устарело.
   Сигнатуры — в `03-calendar-domain.md` §2.
5. **AGP 9: Kotlin встроен** в плагин Android. При ошибках сборки сверяйся с официальной документацией, а не с памятью.
6. **Бэкенд.** Клиент вызывает только RPC-функции. Функции возвращают JSON-конверт `{ok, error}` и **не используют
   `RAISE`** для бизнес-ошибок. Секретный ключ Supabase не попадает в репозиторий и в приложение никогда.
7. **Строки интерфейса — только в ресурсах** (`values/` — английский, `values-ru/` — русский). Русские тексты
   бери из ТЗ дословно.
8. **Зависимости.** Новая библиотека — только с записью и обоснованием в `DECISIONS.md`. Версии — в `libs.versions.toml`.
9. **Секреты и личные данные.** `local.properties`, ключи подписи, токены — не коммитить. В код и документы не
   вставлять имена пользователей, абсолютные пути домашнего каталога, почтовые адреса людей.
10. **Объём.** Делай только текущую веху. Пункты с пометкой **[P2]** — не трогать, пока заказчик не попросит.
    Не переписывай документы ТЗ; расхождения фиксируй в `DECISIONS.md` §5.
11. **Git.** Коммит — только по просьбе заказчика (см. Q-11). `git push` — только по прямой просьбе.

## Когда что-то не сходится

- Документ противоречит реальному API или сборке → выбери решение, ближайшее к замыслу, запиши в `DECISIONS.md` §5, продолжай.
- Не хватает ответа заказчика → возьми значение «По умолчанию» из `DECISIONS.md` §3, продолжай.
- Два документа противоречат друг другу → приоритет: `03` (календарь) > `04` (бэкенд) > `05` > `01` > `02` > `06`; запиши находку.
- Тест на эталонных векторах не проходит → ошибка в коде, не в векторах. Векторы не править.

## Самопроверка перед завершением вехи

- [ ] Полная проверка проходит (тесты, lint, сборка).
- [ ] Для экранов: снимки Roborazzi открыты и просмотрены (светлая/тёмная тема, ru/en).
- [ ] Нет `TODO`, заглушек и закомментированного кода в сделанном.
- [ ] Чекбоксы вехи и «Журнал» в `PLAN.md` обновлены; в отчёте заказчику честно указано, что не сделано или не проверено.
